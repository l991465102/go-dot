# 下拉枚举中文化设计

## 目标

将管理后台所有页面下拉框中的固定英文枚举改为中文标签，同时保持提交给后端、路由筛选和接口查询的枚举值不变。

本次只处理下拉框选项，不修改列表、详情页、状态标签等非下拉区域的显示方式。

## 设计原则

1. 页面显示中文标签，协议继续使用英文枚举值。
2. 相同枚举只维护一份映射，避免不同页面翻译不一致。
3. 映射保持 TypeScript 类型约束，新增或删除协议枚举时能及时暴露遗漏。
4. 已经是中文的下拉选项也接入统一映射，减少组件内散落常量。

## 前端结构

新增集中枚举模块，提供只读的 `{ value, label }` 选项数组。组件使用 `value` 绑定表单和接口参数，使用 `label` 渲染用户界面。

## 页面范围

- 点位管理筛选下拉框。
- 点位新增和草稿编辑向导。
- 点位详情中的开发状态下拉框。
- 业务分类新增和编辑弹窗。
- 属性 Schema 类型与数组元素类型下拉框。
- 项目创建、项目设置和成员管理下拉框。
- 统计分析、自定义报表及其他页面中的固定枚举下拉框。

动态数据下拉框（项目、分类、点位、报表、负责人等）继续显示数据自身的名称，不进入固定枚举字典。

## 兼容性与错误处理

- 所有 `<option>` 和 Element Plus `<el-option>` 显式绑定英文 `value`，不能依赖标签作为值。
- API 请求、URL 查询参数、缓存数据和表单模型不做迁移。
- 如果后端未来返回字典中不存在的新枚举，下拉框不静默替换协议值；开发阶段通过类型和测试发现并补充映射。

## 测试

1. 枚举模块测试每个协议值对应预期中文标签。
2. 点位管理测试筛选下拉显示中文，选择后查询参数仍为英文枚举。
3. 点位向导测试行为、平台、属性类型等中文选项和英文表单值。
4. 分类、项目设置和详情页测试各自下拉框中文标签。
5. 运行前端单元测试、类型检查和生产构建。

## 不在本次范围

- 列表、详情、状态标签的中文化。
- 后端字典接口或数据库字典表。
- 用户自定义枚举标签。
- 修改任何后端枚举协议值。
