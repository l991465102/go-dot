# 自定义报表宽表展示与 Excel 导出设计

## 背景

当前自定义报表查询接口按“日期 × 点位”返回长表数据，页面和 Excel 的“数据明细”也逐条展示日期、状态、点位信息、PV、UV 和 UV 口径。

用户需要把选择的点位按日透视为宽表，使页面查询结果和 Excel 数据明细采用相同格式：

| 时间 | dot_10010_pv | dot_10010_uv | dot_10086_pv | dot_10086_uv |
| --- | ---: | ---: | ---: | ---: |
| 2026-07-12 | 6 | 4 | 0 | 0 |
| 2026-07-11 | 6 | 4 | 0 | 0 |
| 2026-07-10 | 10 | 5 | 0 | 0 |

## 目标

- 查询结果每个自然日只显示一行。
- 第一列固定为 `时间`。
- 按用户在报表中调整后的点位顺序生成指标列。
- 每个点位固定生成相邻的两列，先 `{point_code}_pv`，再 `{point_code}_uv`。
- 日期按降序显示。
- 缺失的日期点位数据补 `0`。
- 页面与 Excel 的数据明细保持相同的列名、列顺序、日期顺序和数值。

## 非目标

- 不修改 ClickHouse 查询和 PV、UV 统计口径。
- 不修改自定义报表保存的数据结构。
- 不把动态列直接放入 API JSON 响应。
- 不修改 Excel 的“报表说明”工作表内容。
- 不增加新的统计指标或筛选条件。

## 方案选择

### 采用方案：保留长表 API，在展示层透视

后端查询接口继续返回 `DailyResult.items` 长表。页面将长表转换为动态宽表，Excel 导出器使用同一业务规则将 `DailyResult` 写成宽表。

优点：

- 保持 API 稳定，避免动态 JSON 字段削弱类型约束。
- 不影响现有统计查询、权限、日期校验和报表配置。
- 改动集中在页面展示和 Excel 输出。

### 未采用方案

1. 将查询 API 改成动态宽表：页面处理简单，但响应字段随点位变化，不利于类型约束和接口兼容。
2. 新增专用宽表 API：能保留旧接口，但当前需求不需要维护两套查询契约。

## 页面设计

查询结果区域保留：

- 统计时区
- 点位数
- 天数
- 总 PV

结果表替换为动态宽表：

- `时间`
- 按当前已选点位顺序生成的 `{point_code}_pv`
- 紧邻的 `{point_code}_uv`

原长表中的数据状态、点位编码、点位名称和 UV 模式不再作为结果表列展示。点位信息仍可从报表配置区和统计摘要中获得。

页面透视规则：

1. 以 `DailyItem.date` 为行键。
2. 以 `DailyItem.point_id` 匹配当前查询结果中的点位。
3. 每个日期、每个点位分别填入 PV 和 UV。
4. 未出现的组合使用 `0`。
5. 日期按 `YYYY-MM-DD` 字符串降序排列。
6. 动态列按照当前报表的点位顺序生成，不按编码重新排序。

## Excel 设计

Excel 继续包含两个工作表：

1. `数据明细`
2. `报表说明`

`数据明细`改为宽表：

- A 列为 `时间`。
- 后续列按照查询点位顺序成对生成 `{point_code}_pv`、`{point_code}_uv`。
- 每个日期一行，日期降序。
- 缺失值写入数值 `0`。
- 首行冻结。
- 第一列使用日期列宽，指标列使用适合数值和点位码表头的列宽。

`报表说明`保持现状，包括报表名称、报表说明、查询范围、统计时区、点位清单、导出时间和导出用户。

点位编码属于配置输入，Excel 表头继续经过公式注入防护，不得产生公式单元格。

## 组件与职责

### Web 宽表适配器

提供一个小型纯函数模块：

- 输入：`DailyResult` 和按用户顺序排列的 `ReportPoint[]`。
- 输出：
  - 动态列描述，包括列键和中文/协议表头；
  - 按日期降序排列的宽表行。

`CustomReportsView` 只消费适配后的列和行，不自行重复拼装键值。

### Go Excel 透视逻辑

Excel 导出器从 `DailyResult.Items` 推导：

- 点位首次出现顺序；
- 日期集合；
- 日期与点位的 PV、UV 索引。

服务层已按照请求中的 `point_ids` 顺序生成 `DailyResult.Items`，因此 Excel 使用首次出现顺序即可保持用户配置顺序。

## 异常与边界

- 无查询结果时，页面保持“暂无统计数据”状态。
- 有日期范围但某点位没有数据时，该点位的 PV、UV 均显示并导出为 `0`。
- 点位编码重复属于非法业务数据；正常服务层解析保证点位 ID 唯一，列名以点位编码生成。
- 最多 100 个点位，因此宽表最多 201 列；沿用现有点位数量限制。
- 最多 90 天，因此最多 90 行；沿用现有日期范围限制。
- 当日数据即使尚未完整，也按当前已有数值展示；宽表不增加状态列。

## 测试策略

### 前端

- 两个点位生成四个指标列，顺序与用户选择一致。
- 每个日期聚合为一行。
- 日期降序。
- 缺失组合补零。
- 页面渲染表头和数值符合宽表格式。

### 后端 Excel

- `数据明细`表头为 `时间` 加成对的点位 PV/UV 列。
- 点位列顺序与请求顺序一致。
- 日期降序。
- 缺失组合导出为 `0`。
- `报表说明`保持存在且内容不回退。
- 点位编码表头不会被 Excel 解释为公式。

### 回归

- 前端单元测试、类型检查和生产构建。
- Go reporting 包测试。
- Go 全量测试。

## 验收标准

选择 `dot_10010`、`dot_10086` 并查询后，页面和 Excel 的数据明细均按以下列顺序展示：

```text
时间
dot_10010_pv
dot_10010_uv
dot_10086_pv
dot_10086_uv
```

日期按降序排列，每个日期只占一行，无数据的指标显示 `0`。
