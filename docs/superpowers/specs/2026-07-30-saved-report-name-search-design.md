# 已保存报表名称搜索设计

## 目标

当单个项目保存的自定义报表较多时，用户可以在“已保存报表”选择框中输入报表名称，快速过滤并选择目标报表。

第一期面向单项目不超过 100 个保存报表的场景。

## 范围

### 包含

- “已保存报表”选择框支持输入搜索词。
- 仅按报表名称进行本地、不区分大小写的包含匹配。
- 搜索结果继续使用当前已经加载的 `reports` 列表。
- 清空搜索词后恢复显示全部保存报表。
- 没有匹配结果时显示“未找到匹配报表”。
- 搜索过程不清空或切换当前已经选中的报表。

### 不包含

- 不搜索报表说明、点位名称或点位编码。
- 不增加服务端搜索、分页或数据库索引。
- 不修改报表保存、加载、更新和删除接口。
- 不修改数据库结构，不新增迁移。

## 交互设计

“已保存报表”继续使用现有 Element Plus `el-select`，增加 `filterable` 能力，并设置：

- 搜索提示：`输入报表名称搜索`
- 空结果提示：`未找到匹配报表`
- 保留现有 `clearable` 行为
- 保留现有加载、禁用和选中状态

Element Plus 在本地对每个选项的 `label` 执行过滤；选项 `label` 保持为报表名称，因此搜索范围天然限定为名称。

## 数据流

1. 页面加载项目下全部保存报表。
2. 用户展开“已保存报表”选择框并输入名称。
3. `el-select` 在浏览器中即时过滤已有选项。
4. 用户选择结果后，继续调用现有报表详情加载流程。
5. 清空搜索词只恢复选项列表，不改变已经加载的报表配置。

## 异常与边界

- 报表列表加载失败时，沿用现有错误提示。
- 空搜索词显示全部报表。
- 中文、数字和英文名称均按 Element Plus 默认包含匹配处理。
- 搜索无结果不发起额外请求。
- 项目切换、报表新增或删除后，沿用现有列表刷新逻辑。

## 测试

前端组件测试至少覆盖：

1. “已保存报表”选择框启用 `filterable`。
2. 搜索提示和空结果提示符合设计。
3. 搜索能力不改变现有报表选择、清空和加载行为。

不需要新增后端测试或数据库迁移测试。
