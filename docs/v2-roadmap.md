# go-dot 2.0.0 开发路线

以下为 2.0 历史规划，当前产品以点位定义、上报和统计分析为主，独立的埋点需求模块已移除。

## 交付顺序

1. 埋点需求：需求包含目标、业务场景、需求链接、提出人和期望时间；一个需求关联多个点位。按平台拆分接入任务，记录负责人和进度。现有点位定义状态与接入任务状态分开。
2. 接入验收：隔离测试和生产的写入、查询及统计；展示指定点位的近期事件和校验结果，记录验收人、结果及说明。诊断数据默认脱敏。
3. 接入工具：提供 Web 和 Go SDK，处理事件 ID、批量上报、逐事件结果和可重试错误；根据已发布定义生成类型。
4. 分析：完善趋势比较及筛选，以真实业务场景验证漏斗。先确定身份关联、事件顺序、转化窗口、去重和数据保留口径。

## 实施约束

- 保留已有项目、点位、已发布快照和历史报表的含义；数据库变更使用增量迁移。
- 测试事件不能进入生产统计；上线之前验证采集、明细、实时统计、聚合和报表各环节的环境隔离。
- 需求和任务权限由服务端检查；状态变化与验收应保留操作记录。
- 不把队列接收成功等同于数据已入库或验收通过。
- 匿名身份与登录身份的关联、历史事件保留时间及漏斗口径需要在实现对应功能前明确。
- 每阶段以实际端到端业务流程验收；测试脚本存在不等于已完成验收。

本文件记录历史规划；独立埋点需求模块已移除，历史数据表保留。
